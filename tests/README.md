# 产品验收策略

按 2026-09-04 用户确认的要求，仓库最终只保留一条通过正常入口运行的产品 E2E。
当前先暴露后端能力，再共同确认该 E2E 的场景和断言；本目录暂不包含自动化测试，
不得把未收集到测试或旧固定场景通过报告为产品通过。

旧 unit、integration、contract、smoke、原型 E2E 及辅助脚本已退役，仍可从 Git 历史查阅。
不把这些文件迁移到仓库内的其他目录，也不重新建立一套长期测试体系。

工作顺序：

1. 实现并暴露正常 CLI/API 能力，让用户能实际查看和使用。
2. 能力明确后确定唯一产品 E2E，不让测试代码代办生产装配、规划或关键交互。
3. E2E 或正常使用失败时，必要的定位单测写在仓库外临时目录，通过 `uv run pytest <临时文件>` 定向运行。
4. 修复后复测原失败路径；定位文件不提交、不复制回仓库，也不默认晋升为永久回归测试。

Ruff、格式、类型检查和生成 Client 的构建仍可使用，它们不是新增测试套件。
完整策略与模块职责见 [Product Scope](../docs/PRODUCT_SCOPE.md)，实施顺序见
[P2 Implementation Plan](../docs/P2_IMPLEMENTATION_PLAN.md)。
