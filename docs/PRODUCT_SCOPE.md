# 产品范围与职责

更新：2026-11-07。本文只写产品的目标形态：是什么、按什么主线组织、各模块拥有什么。
它不说明哪些已经实现（见 [STATUS](STATUS.md)），也不排顺序（见 [ROADMAP](ROADMAP.md)）；决定的日期与出处见 [DECISIONS](DECISIONS.md)。
本版按 [产品点清单](PRODUCT_POINTS.md) 重写：现有的点全部保留，只排序归并 [N16]。
方括号里的编号（如 [E13]、[N11]）指向清单条目。

## 1. 一句话与目标

EHAI = Enhanced Human Agent Interface：一种比聊天更高效的人与 Agent 协作方式 [N1]。

- 叠加在用户已有的 Agent 订阅（Claude Code、ChatGPT/Codex，订阅不开放成 API）以及 Pi 之上，
  在用户掌控下编排任务，尽量提高同时推进的项目数 [N2]。
- 用户同时委托多个项目，离开后项目仍在推进，回来直接查看成果、处理必要的决策 [E3]。
- EHAI 是通用 Agent 平台的规划/执行核心；编码是第一个场景，不是永久边界 [E1]。
- 价值看可信成果、人工介入负担和恢复能力，不看 Agent 活动量或新增模块数量 [E4]。

## 2. 主线：一个人，一个入口，很多件事

用户的时间是连续的、单线程的，生活和工作都由同一个个人 Agent 照看 [N3]。

**一个注意力入口。** 个人 AI 对话框只有一份注意力 [N5]。页面上只有一个注意力队列，
按“需要你处理 / 进行中 / 已完成”排列，生活和工作只是标签（C3）。
“需要你处理”的每一项写明原因、证据、可选动作、影响和处理后的恢复路径 [E6]。
这个队列只聚合人工请求，保留源对象、版本和对应操作，不把回复、批准、Gate 判定和恢复合并成一个隐式动作 [E59]。
便签保存问题、证据、多轮消息和明确决定；讨论不解除阻塞、不审批、不扩权 [E58]。

**用对话代替手填和筛选。** 个人 Agent 是用户与实际干活的 Agent 之间的桥梁 [E60]。
任务一复杂，图和卡片就读不过来，人工筛选也不现实，所以由一个可以对话的 Agent 审阅多个任务，
像 Codex、Claude Code 那样用图标和内嵌元素回答 [N4]：

- 助手不自己推导状态，只查询 EHAI 的结构化事实（线程、待办、轨迹）；回答里的卡片由页面
  按核心的实时数据画出，模型只给出引用，所以编不出状态，点开即到图（S3）。
- 不把 JSON 直接丢给用户，回复是人话 [N14]。
- 助手是独立于 Planner 的模型角色，只经公开接口操作；批准、授权、人工检查和整合只给按钮，由用户点击 [E61]。

**入口的两种形态（C1）。** 页面上的内置助手是唯一的对话入口，经 Hub 运行在 Codex 或 Pi 上；
用户自己的 Codex 会话也能经 CLI/MCP 调用同一套能力和轨迹（Claude Code 暂不在计划内，见第 5 节）。外部顶层 Agent 继续可以使用核心，
不需要迁入 EHAI，也不等于 Planner [E2]。

**结果先于轨迹。** 先显示已验证的成果、当前进展和未决问题，原生会话与日志按需展开 [E7]。
项目是目标、任务、成果和执行边界，跨项目总览帮助找到当前的工作 [E5]。
工作台首页是卡片：一眼看清，点开看细节，注意留白 [E53]；页面首版优先“需要我处理 / 正在推进 /
已验证成果”，看板、甘特图、日历和自定义组件不是首批依赖 [E51]。

## 3. 工作：规划、执行与把关

目标是让 Agent 按用户的思路长时间执行任务，不跑偏，由 Gate 把关 [N6]。语义细节见 [执行模型](EXECUTION_MODEL.md)。

**线程。** 线程是面向用户的一级对象：一个 Goal 的讨论、方案、Run、待办与成果 [E44]。
线程的阶段和下一步由核心推导，前端只渲染 [E46]；时间线只来自已持久化的事实，查不到来源的不补造 [E47]。

**规划。** 两条入口：委托 EHAI Planner 生成方案和图，或导入外部 Agent 生成的方案和图；
绕过 Planner 不等于绕过校验、Gate、批准和授权 [E13]。默认由 EHAI Planner 规划，Planner 运行在用户选择的 harness 上（C2）。

- 方案须说明需求、范围/排除项、接口、任务输入输出、依赖、Phase/Reviewer、Gate、权限与失败处理 [E14]。
- 计划支持分支、依赖汇合、有序 Phase 和 Reviewer Gate；跨阶段不能绕过前一阶段的 Gate [E17]。
- Planner 不得静默扩大用户判据；只按 Worker 能力预览规划，缺少能力时用便签请用户决定 [E18]。
- 外部计划不能携带伪造的成功、批准或成果来源 [E16]。

**批准与过程调整。** 批准固定需求、对外接口、Gate 和授权；批准内的过程变化可追踪地进行，
改变批准边界必须回到用户 [E15]。

- 批准内调整走提案 → 独立审查 → 应用；Planner 能看到已完成成果清单和 Check 状态，可只读读取成果 [E19]。
- 过程版本记录 block_changes；改变边界后可显式接续前一个 Run，复用的成果重新经过新 Gate [E20]。
- 项目规则是不可变版本，Run 捕获快照，规则更新只影响后续执行 [E21]。

**执行与判定。**

- 候选、handoff、节点完成、Gate 通过和 Run 完成是不同的事实；检查结果绑定实际成果版本 [E23]。
- Reviewer 提供证据，宿主做自动或人工判定；Worker 和 Reviewer 不能自行宣布 Gate 或 Run 成功 [E24]。
- 自动 Check、人工判断和 Reviewer 意见是不同的事实；Pi 不是安全沙箱，EHAI 管工作区、凭证和副作用 [E33]。
- 区分 pending / stalled / suspended；Attempt 保留真实的成功、失败、中断或未知结果 [E25]。

**人工介入与防跑偏。**

- 人工介入带目标、原因、证据和 request token；回复只解决对应问题，不扩权 [E26]。
- 同一节点每累计 3 次干预就暂停空闲的 Run，等待明确决定 [E27]。
- 周期审查（600 秒或 30 步）只给建议，不自动采纳 [E28]。

**隔离、恢复与成果。**

- 并行写入使用 EHAI 自有的 Git worktree，按依赖整合；integrate-run 自动整合，冲突保留待处理 [E29]。
- 有效 handoff 和已完成成果是恢复依据；未知副作用不能靠换 Session 盲目重放 [E30]。
- 核心止于创建分支，推送和开 PR 归用户或外部 Agent [E32]。

## 4. 轨迹与图

**工作轨迹 [N11]。** EHAI 记录一条与 harness 无关的工作轨迹，写明这件工作已经做了哪些步骤：
阶段、节点、Attempt、关键工具操作、判断、Gate 结果、用户决定和成果。任何 harness 接手时读这条轨迹继续，
因此在不同 harness（如 Codex 与 Pi）之间切换时流程对齐、迁移成本低。EHAI **不**同步各 harness 的 messages、
MCP/system tools、prompt 和 skills，它们由各 harness 自己管理。

- 有效成果/handoff 的业务接续由 EHAI 管理，模型上下文压缩由 harness 管理；EHAI 不重建模型历史 [E31]。
- 后续工作从有效成果、决定和 handoff 继续，减少重新解释与重复探索 [E8]。

**图 [N7]。** 用图显示工作树：阶段、Gate、子步骤、尝试过的路径和每一步的判断，与轨迹使用同一份数据。
现有执行图是页面内分层布局、可平移缩放的画布，Attempt 轨迹按需读取 [E52]；它目前只画计划，
尝试过的路径和判断还要补上。

## 5. Agent harness

Agent Runtime 外置：EHAI 不维护模型循环、Responses Adapter 或上下文算法，所有角色都用现成的 Agent [E11]。
先用透明的 Pi 实现 agent loop，是因为旧项目先用专有平台时测试困难、GPT 陷入循环 [N10]。

- 经 Hub 接入多种 harness（Pi、Codex、Claude Code、OpenCode 等），不修改 harness，只用其公开接口 [E35]；
  前沿闭源模型先接 ChatGPT/Codex，并继续适配 GPT [N8]（C5）；Claude Code 于 11-05 移出计划，
  现有兼容层保留、不再推进，重新纳入由用户决定。
- 接入专有 harness 前，先有一套录制/回放的测试手段，避免重演旧项目的测试困难（S2）。
- Pi 必须保留，作为最后的兜底：没有 Codex 也没有 Claude Code 时照样能用；能接其他模型；轻量、免费 [N9]。
- 三层结构：核心 → Hub → 兼容层；核心拥有全部事实，Hub 不持久化、不判定完成 [E36]；Hub 可以作为独立进程运行，
  跨机器时工作区如何到达还未决定 [E42]。
- 完成只认结束工具，自然语言说“完成”不算 [E37]。
- 新 harness 不改核心枚举：执行配置为 `harness: {kind, version, settings}`，兼容层声明能力，调度按能力匹配 [E38]。
- EHAI 工具经每会话 MCP 端点交给 harness；Claude Code 兼容层关闭内置工具，只用 EHAI 工具 [E39]。
  Codex 例外（11-06 决定 X1）：保留它的原生 shell 与改文件工具，由 EHAI 按角色授权限制并逐项审批，见 [Codex harness 设计](CODEX_HARNESS_DESIGN.md)。
- harness 使用隔离的配置目录，不读用户的全局扩展和认证 [E40]。
- Planner、Worker、Reviewer 是同一后端的不同预设，职责分开；harness 内部的计划不能替代 PlanRevision、Run 和 Gate [E41]。

## 6. 生活：待办、流程与外部服务

Project 表示业务归属，workspace 表示执行环境，两者不是一个概念 [E12]。生活事务和工作进同一个注意力队列（C3）。

**待办与提醒。**

- 独立的生活 Project 处理日常事务：原文或结构化录入、人工确认、待办管理、定时回顾 [E64]。
- 助手管理生活待办：记下、查询、改期、完成 [E63]。到期时 EHAI 经桌面外壳发系统通知，与新待办通知共用一套（C6）；
  [E63] 原先写的“EHAI 不发提醒”由此改变。

**流程与 Routine。**

- Routine 面向订票、行程和日程提醒等，不限于待办和回顾 [E65]。
- 用户或外部 Agent 自定义 Workflow（条件分支、人工决定、等待）；Routine 只负责触发，业务由步骤和 Connector 完成 [E66]。
- Workflow 内不再造 Planner/Worker 循环，开放的推理、研究和编码委托给核心 [E67]。
- 触发方式：一次性、固定间隔、外部事件、带时区的日历规则；“每隔 24 小时”不等于“每天 09:00” [E72]。
- 业务结果（如无票）不等于技术失败 [E71]。
- 扩展点：动作注册、步骤处理器、触发适配器、子流程、Agent 委托 [E75]。

**外部服务与授权。**

- Connector 是独立进程，使用版本化 HTTP 协议，任意语言都能实现；新增服务不改调度器 [E68]。
- 有副作用的动作（预订、支付、写日历、发通知）按具体动作授权，可以持续授权或逐次确认；
  确认要绑定候选项、价格或上限、对象和有效期 [E69]。工作与生活用同一个授权/决定原语，进同一个队列（S1）。
- 先保存调用意图再发请求；结果未知时交给人，不换新键重试 [E70]。
- 首个真实 Connector 是 Google Calendar；目标场景为查票 → 分支 → 批准 → 预订 → 写日程 → 等待 → 通知 [E73]。
- 没有真实账号和供应商契约时，不宣称支持实际购票；需求本身不授权购买 [E74]。

**由 Agent 执行生活事务。** 有浏览器控制和 computer use 的 Agent 在用户授权后执行生活事务 [N12]。
前置工作是接通不依赖 Git 工作区的 Agent 委托（C7）；现有 Pi 核心带代码工作区装配，这项委托还没接通 [E67]。

**大量生活数据的快速判断 [N13]（C4）。** OpenAI Decisions 用来对大量生活数据做快速判断和并行处理，
例如多平台社交媒体趋势、邮箱快速筛选、内容筛选，类似 Jev 提供的示例应用。它是通用模型，
不需要像垃圾邮件分类器那样训练；不让前沿模型处理这类数据，以求执行效率。
Decisions 做成 Workflow 里的 Connector 动作，按数据流批量、并行地筛选（S5）。

双反馈环降为隐藏的实验，以下决定作为历史保留：

- 快环在批准的只读配方目录内处理熟悉的请求，慢环处理升级并提出候选，回放通过后由用户明确发布 [E76]；
  用户纠错会暂停配方，并把请求交回慢环 [E77]。
- 固定的 escalate → Pi 回退：只读的 Pi 角色回答当前请求 [E78]。
- 慢环可以把代码或流程修改交给明确绑定的独立 Project，走正常的计划和批准；不改运行中的框架，不自动部署 [E79]。
- 版本化流程包（配方描述、脚本、分支）：Pi 提修订，用户看过 diff 后发布；这是目标设计，未实现 [E80]。
- 快环于 11-04 改用 OpenAI Decisions [E81]；这一实现于 11-07 放弃，代码中的快环仍是 Jev。

## 7. 引擎、页面与外部接入

- 单一用户入口是本机引擎：init / up / add / doctor，不手写 JSON [E45]；终端与桌面 App 两个前端共享同一状态 [E48]。
- 多工作区管理器托管多个独立的本机核心，按 workspace_id 路由和聚合；不让多个 Planner 共同编辑一个计划 [E43]。
- Tauri 桌面外壳，新待办发系统通知；凭证只继承登录 shell，EHAI 不保存凭证 [E49]。
- 页面只消费生成 Client，不读库，不复制状态机 [E50]。
- 以下三点 11-07 由用户放弃，不再是目标（保留原文以便追溯）：
  - 选中不是 Git 仓库的文件夹时，确认一次即可一键初始化 [E54]。
  - 权限分三档，仿照 Codex（只改文件 / 改文件并运行命令 / 完全访问）；没有沙箱，页面写明 [E55]。
  - 助手可以运行终端命令：只读命令自动运行，其余在弹窗里由用户批准 [E62]。
- 页面要好看：设计以 frontend-design skill 作美学参考 [E56]，并在 GitHub 上找与人类审美对齐的 skill [N15]。
- 外部 Agent 通过事件消费连接核心；固定事务逐步交给 Workflow/Routine [E9]。
  持久事件消费在断线后补领，确认不执行任何业务动作 [E57]。

## 8. 交付原则

- 核心优先；每次交付一个经正常入口可用的小闭环，再按真实使用决定下一步，不要求先建齐全部后端 [E82]。
- 先走通正常入口，再做产品验收；HTTP 200、静态检查通过或字段存在都不等于交付 [E83]。
- 只保留一个产品 E2E；诊断只在实际失败时于仓库外进行 [E84]。
- 多租户、跨项目公平调度和分布式平台不是前置条件 [E85]。
- Token/费用硬限额暂缓；用量区分缺失、零值与估算，费用投影不等于账单 [E34]。
- 旧 Personal Dashboard（PAO）的全量范围、代码、测试门和状态机不自动成为 EHAI 的要求 [E10]。

## 9. 不做与远期

- 不做自动分解或“先粗后细”规划（中型任务直接规划已满分）[E22]。
- 远期候选，真实使用后再立项：
  - 复用经验：把稳定成功的方法提炼为模板、Skill 或 Workflow 建议，来源可追溯，启用需确认 [E86]；
  - 生活日程、日历及更多业务连接器，简单事务不包装成复杂计划 [E87]；
  - 扩展生态、跨项目资源策略、多设备执行 [E88]。[E88] 中的“更多执行后端”已按 C5 调整：Codex/GPT 现在做，Claude Code 暂不在计划内。

## 10. 模块所有权

| 模块 | 所有权与输入输出 | 不拥有 |
| --- | --- | --- |
| 个人助手（内置，C1） | 用户对话、新建线程、向 Planner 转述、汇报进度；查询结构化事实并引用它们回答；生活待办 | 批准、授权、人工检查、整合；自己推导状态 |
| 外部顶层 Agent | 用户意图、解释、跨任务决策，经 CLI/MCP 调用公开能力并读取轨迹 | 数据库状态、隐式批准 |
| 注意力队列 | 聚合人工请求与待决授权（工作与生活），保留源对象和版本 | 把多个动作合并成一个隐式动作 |
| Planner | 调查/讨论、方案和图、批准边界内的过程提案 | 扩权、执行完成判定 |
| 计划管理 | 版本、外部导入、契约与批准关系 | 模型循环 |
| Orchestrator | 节点/分支/Gate 推进、成果与人工介入 | 重新定义用户需求 |
| Scheduler | 依赖、容量、Endpoint、租约与隔离后的派发 | 方案审批、任务验收 |
| 工作轨迹（N11） | 已发生的步骤、判断、Gate 结果、决定和成果，供图、助手和任一 harness 读取 | 各 harness 的原生消息、工具、提示词与 skills |
| Hub 与兼容层 | 会话生命周期、事件归一化、权限翻译、每会话 MCP 端点 | 任何业务事实；完成判定 |
| harness（Pi / Codex 等） | 模型调用、工具循环、原生会话与压缩 | EHAI 业务状态与授权 |
| Worker/Reviewer | 候选成果、证据、审查意见 | 自行宣布 Gate/Run 成功 |
| Workflow / Routine | 生活流程的确定步骤、触发、等待与人工步骤 | Planner/Worker 循环 |
| Connector（含 Decisions 动作） | 外部服务调用、结构化结果、外部事件 | 后续执行决定、凭证外泄 |
| CLI/HTTP/MCP | 同一核心的交互与传输 | 第二套调度器 |
| 工作台页面 | 渲染队列、线程、图与助手回答；经公开接口提交动作 | 核心数据库、另一套状态机、直接控制 harness |
