### M1 注意力队列

`GET/PUT /api/v1/life-binding`（存于数据目录 `life-binding.json`）与 `GET /api/v1/attention`。
一次通过：未绑定时全部为工作并给出提示；绑定 trial 的生活项目后，逾期待办与无线程的确认项为“需要你处理”，
未到期待办与空闲线程为“进行中”，已完成的待办与阶段 ① 线程为“已完成”，生活标签只出现在绑定项目上。
PUT 对未登记工作区 404、缺字段或多字段 422；生活项目不存在时给出提示；停止的工作区列在 unavailable，
其余照常显示。接受的限制：绑定中的 project_id 不是 UUID 时该工作区记为不可用，而不是给出提示。

### M2 助手

两次干预：

1. 只读沙箱会批准工作区内命令。授权一个窄改动：`AgentRoleConfig.allow_native_commands`（默认 True，
   其他角色不变），为 False 时拒绝全部原生命令；助手角色设为 False。
2. 收件箱列表只含待处理项、Run 结果没有 diff 统计。决定：不改核心；收件箱引用只能指向回答时仍待处理的项，
   服务端写入 `inbox_kind`，之后按 `GET /api/v1/inbox/{kind}/{request_id}` 读；diff 统计只从已有整合的
   diff 计算（只给计数，不把 diff 文本交给模型），没有整合时报告不可用。

两次拒绝后返工：

1. Codex 适配器拒绝 `state_root` 设置（只有 Pi 接受），第一条消息即失败。改为只对 Pi 传；同时按 Reviewer
   意见：`allow_text_only` 只对助手开放（其他角色保持原错误路径）、用户原文脱敏后再存与使用、拒绝 `~~~`
   代码块、`reply` 报错写明违反的规则、助手目录 0700。
2. Pi（DeepSeek `deepseek-flash`）首轮以纯文本结束、没有卡片，不满足“助手可运行在 Pi 上”。团队负责人在
   仓库外的本地副本上诊断：会话结束而无结果时在同一会话补一次提醒，并加强提示词，6/6 轮以 `reply` 结束、
   带 5–6 个有效引用。返工实现 `finish_reminder`、改提示词；另修正回答按 UTC 说“今天到期”（提示词要求换算本地时间）、
   `read_run` 误收 Workflow 运行 ID，以及 diff 读不到（409 “Retained integration diff is missing”）时整个
   `read_run` 失败（改为只把 diff 统计标为不可用）。

通过时的核对：Codex 两次回答“手上的事怎样了”（18–22 秒，6 个有效引用，与队列一致）；Pi 4/4 以 `reply` 结束、
5–6 个引用，时间按本地说（“明天凌晨到期”）；问阶段 ① 的 Run 时读到线程与 Run，并说明 diff 统计不可用。
忙时第二条消息 409；回答中途停止管理器，记录“interrupted by shutdown”且无 Codex 进程残留；用户原文中的
假密钥存为 [REDACTED]；要求输出 JSON 代码块或执行 shell 命令时以普通文字回答、无原生动作；离线核对此角色
拒绝命令与文件改动、其他角色不变。校验器拒绝 UUID、JSON、两种代码块与内部名称并给出原因，接受普通句子、短
commit 哈希与 diff 计数。

### M3 首页

两次拒绝后返工：

1. 浏览器中（1440 与 375 px）两栏/手机先助手、无横向滚动；页面提问得到 Codex 6 张卡片；卡片上“完成”同时
   更新新旧回答中的卡片与队列；收件箱卡片打开现有确认面板并保存。拒绝原因：空闲时卡片轮询（20 秒 36 个请求）；
   消息列表铺在页面里，手机上队列被推到约 2200 px 以下；未来到期时间显示“刚刚”；队列里收件箱项用核心的英文问题；
   卡片显示核心的英文不可用原因与错误码。
2. 复查：空闲 20 秒 0 个请求；消息列表在自己的区域滚动、输入框始终可见；未到期待办显示“明天 01:35”；在页面上经
   Pi 提问得到 5 张卡片；从线程卡片进入线程页通过 slugify 的人工检查后，队列与两条旧回答中的卡片都变为
   “已完成 · 取得成果”。拒绝原因：页面加载后消息列表停在中间（scrollTop 870/2002），判断为程序滚动的滚动事件
   把“跟随底部”关掉；另外队列读取失败与不可用工作区仍会显示核心原文。

最终复查时发现，上面“停在中间”是在隐藏的浏览器面板里测的：后台页面不跑渲染帧，ResizeObserver 回调从不触发
（包装后确认 `observe` 已调用而回调为零），所以它不能证明上一版有错。返工（只有用户向上滚动才关闭跟随）仍然
正确，予以保留。改用无头 Chrome（会渲染帧）在验收管理器上核对：加载后停在最新消息；在底部时内容变高会跟随；
用户向上滚动后内容变高不会被拉回；空闲 20 秒 0 个请求；375 px 下助手在前、输入框在首屏、队列紧随、无横向滚动。
队列加 `plain`、不可用工作区改为“工作区 X 暂时读不到，可能已停止。”只读了代码，未用停止的工作区实测。
候选上产品 E2E 通过（1 passed），最终关卡（静态检查、无漂移、网页构建）通过。处理为 **通过**。
