# ADR 0005：EHAI 只拥有上层编排，Agent Runtime 外置

- 状态：已接受；Pi 角色接线和代表性真实运行已有证据，总验收未完成
- 日期：2026-09-14
- 首选后端：完整 Pi coding-agent，经公开 stdio RPC 接入

## 用户结果与范围

用户希望 EHAI 调用现成 Agent 完成调查、规划、实现和审查，不再维护具体模型循环、
Responses Adapter 或上下文算法。本决定覆盖所有角色，不把“只替换编码 Worker”当成最终迁移。
EHAI 仍是通用 Agent 平台的上层核心，编码是首个使用场景。

## 所有权

| 模块 | 输入与输出 | 所有者与失败行为 |
| --- | --- | --- |
| 目标、方案、批准、过程版本 | 用户需求、Agent 提案 → 可审查版本与批准事实 | EHAI；Agent 提案不能自行批准 |
| 调度、阶段、Gate、人工介入 | 获批工作 → 任务分配、候选验收、暂停或完成 | EHAI；底层结束不等于产品完成 |
| Agent 后端 | 角色、指令、工具配置、会话引用 → 操作事件、用量、结果 | Pi；拥有模型请求、内部工具循环、模型历史、压缩和原生会话 |
| 后端连接器 | 平台调用 → Pi 公共 RPC，Pi 事件 → 平台观察 | EHAI；只适配，不重写 Agent Loop；断线不重发未知任务 |
| 业务工具扩展 | 结构化提案、候选、阻塞说明 → 宿主校验与确认 | EHAI；经 Pi 官方扩展接入，不 fork Pi；工具集须按角色授权 |
| 工作区与成果 | 明确授权、实际代码 → 隔离目录、成果版本与恢复依据 | EHAI/部署宿主；会话可读不代表副作用已核清 |

Planner、Worker、Reviewer 使用同一个后端产品的不同预设；角色职责仍分开。Pi 的内部计划、
会话树和工具状态不能替代 PlanRevision、Run、Gate 或有效成果事实。

## 接入方式

1. 使用完整 `@earendil-works/pi-coding-agent`，不只取 `pi-agent-core` 后重新实现会话层。
2. Python 通过直接 argv 启动 Node/Pi，用 LF 分隔的 UTF-8 JSONL 通信，不经 Shell 拼接命令。
3. Pi 源码不复制入 EHAI。运行依赖在 `agent-backends/pi/` 用 npm 和 lockfile 固定，
   与 `control-plane/` 分离；Node 不合版本时明确失败，不修改系统 Node 或静默降级 Pi。
4. 部署使用独立 Pi agent directory；禁止自动读取用户的全局扩展、认证文件与工作区插件。
   业务所需模型、端点、环境凭证和扩展逐项显式配置，不因依赖存在而授予执行权限。
5. RPC `prompt` 成功只是接收确认。`agent_end` 可能之后仍有自动重试或压缩；
   连接器必须尊重锁定版本的 `agent_settled` 语义，再核对结果，不根据自然语言宣布完成。
6. 模型重试归 Pi；任务重试归 EHAI。请求 ID 仅用于 RPC 关联，不是跨进程幂等保证。
   接收结果未知时不得自动重送 prompt。停止还需处理待发队列并确认空闲，不能只发 abort。
7. EHAI 不解析或重放不透明 reasoning，不再从平台事件重建模型历史。原生会话属于 Pi；
   EHAI 保留会话引用、关联版本、必要业务事件和用量，不公开原始敏感内容。

Pi 不是安全沙箱，工具选择和 Prompt 也不是操作系统权限边界。执行隔离、凭证暴露及未知
副作用处理必须先定义并验证，才可替换当前生产写任务入口。

## 实施顺序与正常入口验收

本节保留决策时的迁移顺序，不是当前待办。2026-09-15 的当前接入、运行证据与未完成项见
[Pi 接入状态](../PI_BACKEND_MIGRATION.md) 和 [STATUS](../STATUS.md)。顶层 Agent 在 EHAI
之外、外部计划导入和 MCP 的补充决定见 [ADR 0006](0006-external-plan-import-and-mcp.md)。

2026-09-14 补充决定：用户明确允许直接删除自研 Runtime，因此不再以完成真实模型迁移验收为
删除旧底层的前置条件。现在旧 Loop/Responses 已移除，所有目标角色已接线到 Pi，但真实工具、
取消/恢复和产品闭环仍未验收。下列原顺序保留决策过程，以此补充和迁移记录为当前实施状态。

1. **后端接通**：固定依赖，提供无模型调用的 `inspect-agent` 正常 CLI 能力，实际启动 Pi、
   查询会话状态并关闭进程。此步骤不证明模型、工具或任务执行已通过。
2. **一个执行纵向闭环**：映射现有 Worker Connector，配置并持久化明确授权，
   通过正常执行入口完成隔离任务、候选提交、宿主成果捕获和既有 Gate；验证停止与恢复。
3. **规划与审查迁移**：接入方案工具、讨论、过程提案、独立边界审查和阶段 Reviewer。
   模型侧工具的定义、参数、返回、宿主校验与持久化一起迁移；不移植自研模型循环。
4. **退役自研 Agent 实现**：所有正常入口不再依赖 Built-in Loop/Responses Adapter 后，
   移除旧实现和冗余配置；历史运行记录保持可查询，不将旧 Session 假装成 Pi Session。
5. **产品验收**：回到用户已确认的唯一 E2E 与真实自举路径。对比实际用量与成果推进，
   不以依赖安装、RPC 成功或模型 HTTP 200 代替交付。

阶段 1 的输入为上游 CLI 路径与 Node 可执行文件，输出为后端版本、协议与隔离会话状态。
不读取任务仓库，不读取模型凭证，不发送 prompt，不创建 Goal/Run，不修改现有数据库。
执行前置失败以非零退出码报告。控制通道超时是握手/收敛期限，不是任务总时长限制。

当前累计源码、未提交改动和旧试用记录都保留。分支只是新的提交位置，不保存未提交文件；
实施前已另作本地源码快照。不会仅为迁移删除旧数据库、重跑旧任务或扩大原授权。
