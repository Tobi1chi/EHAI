# 快环执行代码与流程修订：范围草案

2026-09-25，用户明确了运行实例与目标 Project 的边界：不能直接修改正在运行的框架，
可以修改独立目标 Project；该 Project 可以包含 EHAI 自身源码。
本轮先接通“绑定目标 Project → 慢环提出工程修改 → 目标核心规划 → 正常批准/执行”的
现有编码链路。下方版本化通用流程包/原生分支执行器仍为后续设计，**不是已实现接口**。
本轮代码和分支修改指目标 Project 中的脚本、源代码或流程定义文件，不把它等同于通用
Workflow 编辑/执行引擎或运行框架的自动热更新。

## 已接通：目标 Project 修改入口

控制宿主显式启用固定 Pi 回退，再为 lab 绑定一个独立的本机 EHAI 核心及其中的 Project：

```text
POST /api/v1/routing-labs/{lab_id}/change-project
CLI: configure-routing-project --lab-id <UUID> --file <JSON> --idempotency-key <key>
MCP: configure_routing_project
TS: configureRoutingProject(labId, request)
```

```json
{
  "idempotency_key": "change-project-1",
  "api_url": "http://127.0.0.1:8001",
  "project_id": "<target-project-id>"
}
```

api_url 与 project_id 都显式为 null 时清除未来请求的绑定，只提供一个不合法。
首版只接本机 loopback HTTP 的核心 API，不接受 URL 内凭证、重定向目标或任意接口路径。
宿主从目标正常 get-project/runtime-context 查询实际 Project 身份与工作区，物理解析路径后，
拒绝与当前框架源文件、私有 Pi 配置/运行库、数据库目录或成果目录重叠的目标。
不用仓库名称识别“自身源码”：独立的 EHAI clone/worktree 可以作为普通目标项目；
一个指向当前运行目录的别名或软链接不能绕过路径校验。

绑定随每次 Pi 调用保存快照。Pi 只获得目标说明，不能自行替换 API 地址、项目或路径。
其 finish_routing_fallback 的 project_change 字段可提交具体工程修改目标；未绑定时必须为 null。
工程修改必须 needs_human=true，路由候选及 change_reason 均为 null，不能声称代码已经修改。
Pi 正常收尾后宿主持久保存转交意图，释放本地模型槽位，再通过固定的目标核心接口
创建 Goal 和规划讨论；每一步前重新检查绑定工作区，幂等键来自原请求的调用身份。

原请求的 `fallback.project_change` 保存目标快照、objective、goal_id、conversation_id、
plan_revision_id 和状态。生成计划时为 waiting_approval；需要进一步讨论时为 needs_input。
后续批准、执行授权、Worker 候选工作区、Reviewer/人工 Gate、Git 成果查询全部使用目标
Project 现有接口；转交器没有 approve/start/integrate/push/deploy 权限。
源码修改不会自动部署，也不会令正在运行的 EHAI 实例加载新代码。

拒绝或网络问题保存 failed/unknown，不自动再次发起模型规划；目标已返回的 Goal 身份保留，
操作者可以通过正常项目/Goal/讨论查询核对结果。宿主重启将未完成转交标记 unknown，
不会根据超时猜测目标规划未发生。改变/清除绑定不改写已经领取请求的目标快照。
源请求的转交状态不是目标 Run 的镜像，执行进度应读取对应目标 Project。

## 一次改进的用户结果

快环回退后，Pi 先回答当前请求。若缺少可复用的处理方式，Pi 可以提出完整的新流程版本，
包含配方适用描述、执行脚本和分支定义；验证通过后，用户看到具体 diff、案例结果及权限变化，
再明确发布。后续新请求使用新版本，已有运行继续绑定原版本。

例如“只看今天未完成的事项，没有则显示待确认事项”：
读取生活任务 → 业务脚本按输入日期/时区和状态筛选 → 条件分支判断是否为空 →
返回筛选结果或读取 Inbox。该例需要真实的数据处理代码和分支执行，单改 Jev 描述不能完成。

## 拟采用的模块边界

| 模块 | 输入、输出与所有权 | 失败与验收 |
| --- | --- | --- |
| 版本化流程包 | Project 拥有；配方描述、输入/输出契约、有限无环图、脚本及依赖清单构成不可变版本 | 保存前校验所有引用、默认分支、可达性及代码摘要；错误保留候选，不发布 |
| 修订提案 | Pi 基于明确的基线版本修改候选文件，记录来源请求、修改理由和逐文件 diff | 不直接改生效文件；发布检查基线仍是当前版本，过期提案不能覆盖其他修改 |
| 分支执行器 | 复用既有独立 Run/步骤/调用记录，执行单活动路径，条件与选中出口持久化 | 重启不重新选择已决定的分支；外部调用沿用 Connector 回执及未知结果核对 |
| 业务脚本执行 | 第一版只负责 JSON 输入到 JSON 输出的数据处理；运行固定版本、固定摘要的脚本 | 隔离运行，不把 Python/Node 普通子进程或目录限制当作安全沙箱；失败输出诊断，不把异常当空结果 |
| 验证与发布 | 路由分类回放 + 实际脚本/分支执行 + 独立案例，结果绑定版本与依赖摘要 | 修改任何受测代码/图后，旧通过记录失效；正式发布是单独决定，原记录继续可查 |
| 回退 | 保存已发布版本历史，显式切换后续运行使用的版本 | 不回写历史结果；不假定软件回退可以撤销外部已发生的副作用 |

Jev 继续只选择有限的配方或升级，不负责生成代码、批准修改或宣布执行成功。
内部改进由 Pi 承担；Codex 子 Agent 只模拟用户和观察状态，不代做内部任务。

## 建议权限

1. **候选修改**：Pi 可以修改指定流程包的业务脚本、配方描述、节点、连线和条件，
   但只写入该提案的隔离候选目录，保存基线身份和内容摘要。
2. **验证执行**：代码脚本仅接收快照 JSON，返回 JSON。宿主提供独立执行环境，默认无网络、
   不挂载宿主凭证或业务仓库，只读输入、限定输出目录，并限制运行时间和资源。
   不允许脚本自行安装依赖、读取密钥或绕过 Connector 访问外部服务。
3. **外部动作**：图节点通过宿主已批准的 Connector 动作调用，不在脚本内持有密钥。
   修订若需要新增动作/账号/写权限，形成明确的权限差异，不能沿用旧授权自动启用。
4. **正式生效**：复测完成后由用户明确发布。已运行实例仍绑定旧版本；不自动热替换。
5. **EHAI 框架源码**：允许作为独立目标 Project 的源码进行开发，经过正常计划、审查、批准
   和候选工作区交付。禁止对当前运行安装、私有配置或部署目录直接写入；新源码不自动生效。

上述源代码范围已确认。通用流程包的脚本隔离执行器尚未交付；本轮继续使用目标 Project
既有的执行授权与代码工作区，不因绑定 Project 而自动获得命令、网络、批准或部署权限。

## 实施顺序

1. 建立流程包版本、修订提案、diff、历史查询与带基线检查的发布契约；统一已有配方修订。
2. 接通有限分支图及隔离的数据处理脚本步骤，复用既有执行记录和 Connector 协议。
3. 给 Pi 增加读取版本/提出修订的工具；严格契约使用 Pi 支持的字段形态，继续保留明确结束工具。
4. 执行一条正常接口实验：旧流程回退 → Pi 修改脚本和条件 → 实际复测 → 明确发布 →
   新请求使用新版本，同时验证旧运行/旧成果仍指向旧版本。

首个实验以项目内只读数据为对象，不新增永久测试套件。真实错误才在仓库外做最小诊断，
修复后复试原路径；分类回放通过不能代替脚本执行结果和分支行为验证。
