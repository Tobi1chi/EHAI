## 阶段

2026-11-05 定：执行顺序为 ③ → ① → ② → ④ → ⑤（编号沿用建议 S4）。每个阶段交付一个经正常入口可用的闭环，
完成条件不满足不进入下一阶段，除非用户另行决定。

| 阶段 | 用户结果 | 完成条件 |
| --- | --- | --- |
| ③ Codex/GPT 走正常路径（先做） | 在工作区执行配置里选 Codex，用自己的 ChatGPT 账号跑完一条线程 | 录制/回放：录下真实 Codex 会话的原生输出，不调用模型即可回放驱动兼容层，用于仓库外诊断（不新增永久测试套件）；Codex 兼容层经其公开接口，在正常入口完成一条线程的规划、执行与审查 |
| ① Pi 上的长任务不跑偏 | 一项多阶段的真实编码任务按批准的方案跑完，中途只在 Gate 和确有需要时找用户 | 真实模型、正常入口；方案至少 3 个阶段，含阶段 Gate、人工检查和至少一次批准内过程调整；最终成果满足批准判据，审查中没有方案外改动，干预次数与原因有记录；工作轨迹可按 Goal 读出步骤、判断、Gate 结果与决定；图显示尝试过的路径与判断；同一 Goal 的后续阶段换一个 harness 后，读取轨迹接着做 |
| ② 富元素助手与单一队列 | 问助手“手上的事怎样了”，得到一句话加可点的卡片；首页只有一个注意力队列 | 助手回答中的引用由页面按核心实时数据画成卡片（线程、待办、Gate、diff、生活待办），按钮走现有接口；不向用户输出原始 JSON；生活与工作合成一个队列，只作标签；助手可运行在 Codex 或 Pi 上 |
| ④ 统一授权与生活接入 | 工作和生活中需要用户决定的事出现在同一个队列，用同一种方式确认 | 一种授权/决定原语同时覆盖方案批准、人工检查、Workflow 人工步骤与 Connector 写动作确认（绑定对象、价格或上限、有效期）；到期的生活待办发系统通知；Decisions 作为 Workflow 动作批量筛选一个真实数据流（数据源由用户选定）；路由实验移出页面主路径 |
| ⑤ 由 Agent 执行生活事务 | 用户授权后，Agent 用浏览器或 computer use 办完一件选定的生活事务 | 前置：接通不依赖 Git 工作区的 Agent 委托；每个副作用动作经阶段 ④ 的授权；没有真实账号和供应商契约时不宣称支持购票 |

阶段 ③ 原先的待查事项（订阅登录与隔离配置、使用条款、公开控制接口）已于 11-06 查清，结论与仍需运行确认的事项见

## 推进规则（2026-11-07 定）

| 事项 | 决定 |
| --- | --- |
| 何时停下找用户 | 只在必须由用户来时：方案批准、Gate、人工检查、需要用户登录或授权、真实验收、预算接近上限、开 PR 与合并 |
| 提交与 PR | 一个逻辑改动一个提交，可以细分；全部阶段做完后开一个 PR，合并由用户决定 |
| 真实模型预算 | 每个阶段的按量费用（DeepSeek、OpenAI API）不超过 ¥50，接近上限时停下问用户；Codex 用用户的 ChatGPT 订阅额度，不计入 |
| ① 的真实任务 | 在 EHAI 自身实现 ④ 要用的 RSS Connector：抓取与解析 → 作为 Workflow 动作 → 用法文档与检查；由 EHAI 的 Planner/Worker 执行，方案先给用户批准 |
| ④ 的数据源 | RSS/网页订阅，订阅源由用户给出 |
| ⑤ 的生活事务 | 用用户本机的 [catbus](https://www.npmjs.com/package/catbus-cli) 命令行查询 12306 车次、余票、票价与中转，整理 2–3 个出行方案，不下单不付款。catbus 的 12306 接口免登录、只读，不提供下单等写操作；购票由用户本人在 12306 完成。行程条件到 ⑤ 开始时由用户给出。⑤ 完成条件写的是浏览器或 computer use，改用命令行是否算满足，待用户确认 |
