# P2 收尾计划

更新：2026-09-16。旧逐日增量移至 [历史记录](history/P2_IMPLEMENTATION_PLAN.md)。
范围由 [产品定位](PRODUCT_SCOPE.md)、[执行模型](EXECUTION_MODEL.md) 定义。

目标：通过正常入口完成一项真实项目工作，保留批准、成果与人工回路，遇到中断能明确
恢复依据和下一步。已交付能力及历史试用以 [STATUS](STATUS.md) 为准，不在本页重复列实现清单。

| 工作项 | 输入与预期输出 | 收尾依据 |
| --- | --- | --- |
| 成果与批准接续 | 已有前驱 Run、明确的新批准及来源映射 → 后继 Run 和可追溯成果 | 完善多次接续和异常中断证据；失效输入不得沿用旧成果或 Gate |
| handoff 与恢复 | 已持久执行事实、成果和中断原因 → 正常入口可继续或明确请求人工处理 | 验证执行、产物收尾和恢复的衔接；未知副作用先核对，不用新会话盲重放 |
| 有效上下文接续 | 获批目标、当前有效图、已验证成果、决定与未决问题 → 下一段任务的明确输入 | 核对逻辑 Phase Session 与物理 Pi Session 的连续性目标，避免重复调查；不自研压缩或承诺缓存命中 |
| 产品验收 | 与用户约定的一项真实项目工作 → Gate、成果和控制路径可核对 | 经 CLI/API 的生产装配执行，框架自己派发与收尾，外部驱动不补业务步骤 |

每轮只选一个明确用户结果和完成条件。先接通并使用正常路径，只对实际阻断做必要修复，
修复后重试原路径；旁支问题另记，不把局部交付扩成跨模块重构。没有未知副作用核对结果时，
保留暂停/人工处理和证据，不为了完成阶段而无限重试或改变验收要求。

唯一产品 E2E 仍待约定与收口，不增加常驻测试矩阵；真实调用按当轮用户授权的范围与预算进行。
Token/费用硬限额暂缓，使用指导 Skills 后续安排。

P3 的总览、待办和页面可逐项消费已完成的核心能力；遇到核心阻断回到该路径修复。
不要求核心覆盖所有假想故障才开始上层建设，也不把 P3 界面当作 P2 总验收证据。
本页只列收尾工作；[路线图](ROADMAP.md) 管后续顺序，[实施记录](R2_IMPLEMENTATION_PLAN.md) 管运行证据。
